The follow-up permits one replacement traversal with page size 991, for at most four traversals. Duplicate recovery now requires three complete matching traversals with **zero cross-page duplicates in each**. Only a traversal otherwise valid but containing cross-page duplicates may be omitted from the proof. Short raw counts, malformed IDs, conflicting duplicate payloads, repeated whole pages, oversized pages, changing totals or differing complete within-page identity/content/multiplicity proofs disqualify duplicate recovery. The ordinary exact-distinct-count path remains. Success logs contain only dates and aggregate counters, including the number of attempted traversals. No discarded boundary-tainted rows are merged into the result.

Fraud's existing three-day job window remains unchanged. The live failing May12–14 window contains 2,103 / 2,167 / 2,370 canonical rows respectively (readback 09:34:46 UTC); the three-day atomic RPC hits its inherited eight-second timeout. A Fraud-specific adapter reduces each conversion replacement to one Berlin day, sequentially, using the already fully loaded provider data. The shared store/RPC contract and its eight-second timeout are unchanged. Empty days are also replaced to remove stale rows. After all daily replacements, the service performs the same full original-window SQL readback and type-count/identity-digest parity. Only then may the original cursor and coverage advance.

This is atomic per day, not per three-day job. If a later day fails, preceding daily transactions can already be committed. The persisted Fraud checkpoint remains invalidated and unadvanced; a backfill retry repairs the same full window. The existing normalizer conservatively resets an invalidated rolling checkpoint to backfill from its original windowFrom; a rolling failure can therefore require replaying more historical windows. Cache tags expire after invalidation and on every exit. Each dashboard request reads the current checkpoint before using a cache generation tied to that checkpoint, so a warm previously ready cache cannot conceal invalidated coverage. Before returning, each reader checks that generation again through a fresh non-memoized database read. A changed or unavailable checkpoint fails closed, covering readers already in flight when an import starts. No fallback accepts a checkpoint read error.
